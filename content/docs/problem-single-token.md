# The problem with single-token launches

A standard memecoin launch is a single token in a single pool. That simplicity is its strength — and its failure mode.

## Attention is lumpy, liquidity is not

Memecoins live and die on attention. When attention arrives, one pool absorbs all of it; when attention moves on, the same pool drains alone. There is no structure to spread a spike across anything else, because there is nothing else.

## Creators and holders fight over one fee stream

A single token has one fee switch. Routing fees to holders starves the creator; routing them to the creator starves the holders; burning supply pleases everyone narratively and no one measurably. Every choice is zero-sum because there is only one bucket.

## Launches are one-shot events

A launch happens once. After that, the token either holds attention or bleeds out. There is no built-in mechanism for a second or third act — no reason for a trader who missed the first spike to participate in anything except buying someone else's exit.

## What poof.fun changes

poof.fun replaces the single token with a **narrative of three tokens**, each with its own fee destination, bought through one coordinated transaction. Attention paid to any one token mechanically supports the other two, and the three fee identities stop fighting over a single bucket because each token owns its own.
